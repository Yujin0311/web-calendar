# 清序 · 第四次维修迭代

在第一版原生前端基础上增加 Node.js、Express、SQLite 和 JWT 登录。日历预览、草稿箱、复习节点、冲突提示、课程节假日、CSV/ICS 导出均保留。

第四次迭代在保留全部分类、任务与导出行为的前提下，新增账号级「作息表」、重做图片识别导入的交互与报错位置、给 AI 规划助手加上任务密度与冲突规避、并重排了计划预览页的布局与主导航。本轮改动只涉及前端页面结构、AI 请求参数与一处设置表补列，**不改变既有任务的存储格式**，老账户与老本地缓存可直接升级。分项说明见下方「第四次维修功能」。

## Windows 本地启动

1. 从 [Node.js 官网](https://nodejs.org/en/download)安装当前受支持的 LTS 版本（建议 Node.js 24），并确认 PowerShell 中 `node -v`、`npm -v` 可运行。
2. 在本项目文件夹打开 PowerShell，运行 `npm install`。
3. 运行 `npm start`，看到 `清序已启动：http://localhost:3000` 后，在浏览器打开该地址。
4. 首次使用先注册账户，再登录使用。以后启动只需运行 `npm start`。本版需要后端，不能直接双击 `index.html` 运行。

数据库和本机 JWT 密钥保存在 `data/` 文件夹，已被 `.gitignore` 排除。备份账户数据时，请在停止服务后备份整个 `data/` 文件夹。请勿把它公开上传。

## SQLite 表

| 表 | 主要字段 | 用途 |
|---|---|---|
| `users` | `id`, `username`（唯一）, `password_hash`, `created_at` | 账户和 bcrypt 加盐哈希密码 |
| `sessions` | `jti`, `user_id`, `expires_at`, `created_at`, `last_activity_at`, `expire_at` | JWT 会话与退出失效；最后活跃时间与绝对过期时间（毫秒时间戳）用于空闲/绝对双重超时 |
| `invite_codes` | `id`, `code`（唯一）, `max_use_count`, `used_count`, `is_active`, `created_at`, `note` | 注册邀请码：可限制使用次数、随时停用，备注方便管理 |
| `categories` | `id`, `user_id`, `name`, `color` | 用户独立分类 |
| `user_settings` | `user_id`, `offsets_json`, `default_time`, `holidays_json`, `timetable_json` | 复习节点、默认时间、课程节假日，以及第四次迭代新增的作息表（每节课的起止时间、每天课时数、单节时长与课间） |
| `tasks` | `id`, `user_id`, `category_id`, `name`, `start_date`, `end_date`, `duration`, `reminder`, `time_mode`, `start_time`, `note`, `review`, `all_day`, `plan_group`, `parent_task_id`, `repeat_type`, `repeat_weekdays_json`, `deleted_offsets_json`, `draft_form_json`, `status` | 任务、全天标记、AI 父子关联、重复设置和草稿 |
| `occurrences` | `id`, `user_id`, `task_id`, `offset_days`, `round_number`, `event_date`, `start_time`, `duration`, `completed` | 每条独立日程，可单独删除 |

所有任务表都带用户归属，API 按当前 JWT 用户查询或修改。前端使用 `localStorage` 中的用户专属缓存支持断网时继续查看和编辑，重新联网后同步。当前版本为单设备优先的最后写入覆盖模型，不提供多设备冲突合并。

## API 清单

除注册、登录外，均需请求头 `Authorization: Bearer <JWT>`。

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/api/auth/register` | 凭有效邀请码注册并获得 JWT；同 IP 高频尝试返回 429 |
| POST | `/api/auth/login` | 登录并获得 JWT |
| POST | `/api/auth/logout` | 注销当前 JWT 会话 |
| GET | `/api/auth/me` | 查询当前账户 |
| GET、PUT | `/api/sync` | 读取或整体同步用户计划；前端离线缓存使用 |
| GET、PUT | `/api/settings` | 读取、更新设置 |
| GET、POST | `/api/categories` | 列出、新增分类 |
| PUT、DELETE | `/api/categories/:id` | 修改、删除分类 |
| GET、POST | `/api/tasks` | 列出、新增任务 |
| PUT、DELETE | `/api/tasks/:id` | 修改、批量删除任务及其全部日程 |
| POST | `/api/tasks/:id/draft` | 将任务移到草稿箱 |
| PATCH、DELETE | `/api/occurrences/:id` | 修改完成状态、仅删除本次日程 |
| GET | `/api/export/history` | 查看当前账户的 ICS 导出记录 |
| POST | `/api/export/ics` | 仅导出未记录过的任务，成功响应后记入历史 |
| DELETE | `/api/export/history` | 清空当前账户的 ICS 导出记录 |
| POST | `/api/ai/parse-schedule` | 登录后提交课表图片 data URL 与当前作息表，返回 `{ courses: [...], isValid }`；不写数据库 |
| GET、POST | `/api/notes` | 列出、新增当前用户便签（最多 30 条） |
| PUT、DELETE | `/api/notes/:id` | 编辑、删除当前用户便签（单条最多 250 字） |
| POST | `/api/ai-plan` | 接收目标、日期、基础情况、是否精确到钟点、任务密度与可选高效时间段，并附带用户已有任务的占用时段；返回待确认规划 JSON |

## 苹果日历导入说明

本版继续导出一个完整的 ICS 文件，事件标题中的分类标签和 `CATEGORIES` 字段保留。**ICS 导入不会自动创建独立苹果日历**；在 Mac 的日历 App 中导入时，请选择目标日历。如需独立日历，请先在苹果日历手动新建。

同一任务全部艾宾浩斯日程使用相同的 `SUMMARY`。用户填写的备注保持原文，后面附加「初次学习」或「复习第 N 轮」到 `DESCRIPTION`，用于区分轮次。

## 第三次维修功能

- 新建任务可以选择不重复、每天、每周（多选星期）、每月、每年。手动重复和艾宾浩斯复习互斥。手动重复的预览仍逐日展示，ICS 则写成**一个 `VEVENT` + 一个 `RRULE`**；被单独删除或因课程节假日跳过的日期以 `EXDATE` 表达。艾宾浩斯维持原有不规则间隔的逐条事件。
- ICS 下载只包含当前账户尚未导出的任务，包括任务的艾宾浩斯复习日程。导出记录写在项目根目录的 `export_history.json`，包含各账户最近导出时间和已导出的任务 ID。该文件已加入 `.gitignore`。编辑已经导出的任务后，如需重新导出，请点击「清空导出记录」。清空后下一次会导出当前计划的全部日程。
- 新建任务提示文案已更新。页面右下角增加开发者署名与送花按钮，点击后播放约 3 秒花瓣动画。

## 第四次维修功能

第四次迭代包含六块改动：账号级作息表、图片识别导入交互与报错位置、AI 规划助手的密度与冲突规避、计划预览布局重排、便签与署名折叠、新建任务的新增分类与「全天」语义。既有任务的存储格式、复习规则、节假日规则与导出逻辑都没有变化。

### 1. 作息表（账号级上课时间设置）

- 位置：「图片识别导入」页面最上方的可折叠「作息表」面板。参数为**每天课时数**（1–20，默认 12）、**单节课时长**（5–180 分钟，默认 45）、**课间休息**（0–60 分钟，默认 5），并提供「按以上参数重排」与「恢复默认」。
- 每一节都可单独修改开始与结束时间（`HH:mm`，24 小时制），可增删节次（最多 20 节，至少 1 节）。默认时间表为 `08:00-08:45`、`08:50-09:35`、`09:50-10:35`、`10:40-11:25`、`11:30-12:15`、`14:00-14:45`、`14:50-15:35`、`15:50-16:35`、`16:40-17:25`、`17:30-18:15`、`19:00-19:45`、`19:50-20:35`。
- 修改某一节的开始或结束时间时，**后续节次自动顺延**：没有单独设置过时长的节次沿用前一节的时长，被单独改过结束时间的节次保留自己设定的时长；顺延过程中若越过当天 24:00 会停止顺延并给出中文提示，不会写入非法时间。
- 数据保存在 `state.settings.timetable`，随 `/api/sync` 落库到 `user_settings.timetable_json`，与账户绑定、设置一次长期有效。默认值与校验集中在 `timetable.js`，前端、后端与 `GET /timetable.js` 共用同一份实现。

### 2. 图片识别导入

- 「选择本地图片」「手机拍照上传」改为**纯展示块、不可点击**，各自下方有一个圆形加号按钮：点左侧加号打开本地文件选择，点右侧加号打开手机拍照。解析进行中，加号按钮与文件输入一并禁用。
- 解析请求会把**当前作息表**一起发送给视觉模型，识别出的节次按作息表换算成具体上课时间；确认页**不再要求手填每一节的开始与结束时间**（原「节次时间表」界面已移除），只需核对课程信息与学期第 1 周的周一日期。
- 报错位置分级：选图、格式/体积、网络失败、超时、AI 返回不合法等**解析阶段**错误显示在课程草稿上方；点「确认并批量生成日程」后出现的**导入阶段**错误（节次超出作息表范围、涉及年份未配置节假日、保存失败等）显示在该按钮**正上方、课程草稿下方**，并自动滚动到可见位置。

### 3. AI 规划助手

- 新增「任务密度」滑块三档：**轻松**（整个规划期每周 1–2 个子任务）、**中度**（平均每 2 天 1 个子任务，默认）、**忙碌**（每天 1 个子任务）。三档对应三套内置提示词，服务端按所选密度换算出目标子任务总数。更改密度或高效时间段后，已生成的规划会被清空并要求重新生成。
- 每次生成规划时，除了目标、起止日期、基础情况、是否精确到钟点与高效时间段，还会把用户在所选区间内**已有日程的占用时段清单**（开始时间、时长，全天任务单独标注）连同隐藏的系统提示词一起发送给模型，要求新任务不与已有日程重叠、优先安排在高效时间段内的空闲时段、排不下时顺延到最近的有空日期。
- 模型返回后，服务端还会再做一层确定性处理：任务总数超过密度目标时按阶段均匀裁剪（每个阶段至少保留 1 条），与已有日程重叠的任务会被挪到当天最近的空闲时段或邻近日期，且绝不跨越午夜；确实无解时保留原时段（导入时的冲突弹窗仍然兜底），不会静默丢弃任务。「任务密度」只影响本次请求，不写入账户设置。
- 规划结果仍只暂存在当前页面，确认导入后才写入数据库；父任务、子任务、全天任务与复习开关的行为与第三版一致。

### 4. 计划预览布局

- 「搜索全部任务」由独立面板收成一根搜索条，移到「新建任务」按钮左侧。输入关键词后，结果以下拉浮层出现在搜索框下方（含条数统计与批量删除按钮），不搜索时只显示一根空搜索框、不占页面高度；在图片识别导入、AI 规划助手、草稿箱、设置视图下不显示搜索条。
- 「每日任务」移到日历右侧，与日历并排显示；窗口宽度小于 860px 时自动堆叠为单列。
- 「带走你的日程」上移到日历上方；「任务记录 / 日程总数 / 已完成」三张统计卡片移到日历下方、ICS 教程上方。
- 主导航顺序调整为：计划预览、图片识别导入、AI 规划助手、草稿箱、设置，草稿数量徽标仍跟随草稿箱按钮。

### 5. 侧栏折叠

- 左侧「随手便签」与右下角开发者署名卡片各配一个圆形折叠按钮（便签按钮在页面左侧、署名按钮在页面右侧），点击即可收起或展开；箭头方向随状态变化，按钮带 `aria-expanded` 与中文 `title`，键盘可聚焦。
- **每次进入网站都默认展开**，折叠状态只保存在内存，不写入本地缓存或账户设置；未登录时便签与折叠按钮都不显示；便签收起后页面内容自动左移，不会留下空白区域。

### 6. 新建任务：新增分类与「全天」语义

- 弹窗内「任务分类」下方新增「＋ 新增分类」，可直接填写分类名称与颜色。校验规则与设置页完全一致：名称 1–24 个字符、不能与现有分类重名、颜色为六位十六进制、分类总数不超过 200（与 `/api/sync` 的上限一致）。添加成功后新分类立即出现在下拉框中并被选中，设置页的分类列表同步可见，任务弹窗不会关闭、已填写的其它字段不会丢失。
- 选择名为「全天」的分类时，任务**只排到当天、不带钟点**：弹窗自动隐藏「单次执行时长」「提醒设置」「时间设置方式」「开始时间」；保存后日历卡片与每日任务显示「全天」，导出的 ICS 使用全天日期（`DTSTART;VALUE=DATE` 与次日 `DTEND;VALUE=DATE`），并且不参与时间冲突判断与「当日总时长超过 16 小时」提醒。切回普通分类后钟点字段会恢复可用。AI 规划在「不需要精确到几点」时生成的父任务与子任务同样使用这一语义。

### 数据库与缓存迁移

- `user_settings` 表新增 `timetable_json`（默认 `'{}'`）。`server.js` 启动时通过 `PRAGMA table_info` 检测并自动执行 `ALTER TABLE`，老数据库无需手工操作；需要手动执行时使用 `migrations/002_user_settings_timetable.sql`。
- 老账户、老 `localStorage` 缓存（`qingxu-cache-v2-<用户 ID>`）以及离线待同步状态在升级后都会自动补上默认作息表，不会报错或丢数据。
- `index.html` 引用的静态资源都带 `?v=` 版本号（`style.css`、`upgrade.css`、`auth.js`、`ai-schedule-client.js`、`ai-plan-client.js`、`script.js`）。升级后若仍看到旧界面，请强制刷新一次。
- AI 规划接口新增了 `density` 与更详细的占用时段字段，旧版本前端脚本仍可调用（缺少 `density` 时按「中度」处理）。

## 2027 年节假日补充

- 节假日默认值迁移到 `holidays.js`（`GET /holidays.js`，与 `timetable.js` 一样由前端与测试共用）：沿用 2025、2026 年国务院公布的放假日期，并新增 2027 年元旦 1 月 1 日至 3 日；周六、周日不计入跳过列表，因此 2027 年只有 1 月 1 日（周五）进入跳过日期。
- 2025、2026、2027 年视为「已内置」：手动新建「课程」任务、图片识别导入、AI 规划助手在这些年份建立任务时不再提示「尚未配置节假日」，任务照常生成；2028 年及以后仍按原规则提示到设置页补充。
- 老账户的设置里整年缺少内置日期时（例如还没有 2027 年）会自动补齐并同步；该年已有任何日期时保持用户填写的内容不变，不会覆盖或重新加入用户删掉的其他日期。

## 图片 AI 日程解析

登录后打开「图片识别导入」，先在最上方的「作息表」里确认或修改每节课的上课时间（见「第四次维修功能」第 1 节），再点击「选择本地图片」「手机拍照上传」下方的加号上传一张大学周课表 JPG、PNG、GIF 或 WebP 图片（不超过 6 MB），点击「AI 解析日程」。后端通过 OpenAI Node.js SDK 调用阿里云百炼（Dashscope）的 `qwen3-vl-plus` 视觉模型，90 秒超时，一次返回整张课表的课程数组。**请求会一并发送当前作息表**，识别出的节次按作息表换算成具体时间，用户只需逐项核对、修正、勾选课程并填写学期第 1 周的周一日期，点击「确认并批量生成日程」后才写入数据库。课程按识别到的周次生成每周日程；缺失或无法辨认的日期、节次和周次需要人工补齐。图片会发送给 Dashscope API，不会保存在本项目数据库中。

1. 在[阿里云百炼平台](https://bailian.console.aliyun.com/)开通服务并创建 API Key（AI 规划助手另需 DeepSeek 密钥）。
2. 本地开发：复制 `.env.example` 为项目根目录的 `.env`，把 `DASHSCOPE_API_KEY=`（图片识别）与 `DEEPSEEK_API_KEY=`（AI 规划）后的占位文字替换成真实密钥。运行 `npm install`、`npm start`。`.env` 已在 `.gitignore` 中，请勿提交密钥。也可以直接在系统环境变量中设置这两个变量。
3. Render 部署：打开对应 Web Service 的 **Environment → Environment Variables → Add Environment Variable**，分别添加 `DASHSCOPE_API_KEY` 与 `DEEPSEEK_API_KEY`；另设 `HOST=0.0.0.0` 以允许 Render 代理访问，`PORT` 使用 Render 自动提供的值。保存并重新部署。不要把密钥写进代码或提交到 Git。

原先的本地纯文本识别流程已移除。AI 解析结果可能有遗漏或误读，保存前请人工核对。未配置密钥时，其他手动日程功能仍可使用，图片解析与 AI 规划会分别显示中文配置提示。

## 随手便签与 AI 规划助手

登录后，PC 页面左侧有随手便签栏，可新增、编辑和删除。每个账户最多 30 条，单条最多 250 字，前端和后端均校验。便签保存在 SQLite 的 `notes` 表，接口只使用 JWT 所属用户的 `user_id` 查询；旧数据中的右侧便签也统一显示在左侧。移动端暂不展示侧栏。便签不进入任务快照 `/api/sync`。左侧便签栏可用页面左边的圆形按钮折叠，具体见「第四次维修功能」第 5 节。

「AI 规划助手」会将学习目标、起止日期、基础情况、任务密度、是否需要精确到钟点、可选高效时间段，以及用户已有日程的占用时段清单发送给 DeepSeek。后端仅返回阶段和任务 JSON，不保存提问、回答或聊天历史。服务端会按所选任务密度校准任务总数，并避开已有日程占用的时段。确认页可勾选部分或全部细分任务；导入后创建一条**父任务**，名称直接使用学习目标。每项勾选的子任务单独保存为任务记录，并把自身名称、阶段和 AI 复习建议写入自己的备注。父任务备注不堆放子任务列表，复习开关默认关闭，由用户在导入前手动勾选。删除父任务只解除子任务关联，不删除子任务。选择不精确到钟点时，日程使用「全天」分类，ICS 使用 `DTSTART;VALUE=DATE` 和次日 `DTEND;VALUE=DATE`；数据库内部用 `00:00` 占位，页面不显示钟点。放弃或退出时丢弃 AI 结果。

计划预览页顶部的「新建任务」按钮左侧有一根搜索条，可搜索当前账户全部任务的名称、分类和备注；输入关键词后结果列表出现在搜索框下方，每条结果对应一条任务记录，可多选后一次删除，删除前会显示影响的任务与日程数量。清空输入即收起结果，不占用页面高度。草稿不包含在搜索结果中。

旧数据库启动时自动执行下列幂等检查与迁移；新数据库的 `CREATE TABLE tasks` 已含对应字段：

```sql
ALTER TABLE tasks ADD COLUMN all_day INTEGER NOT NULL DEFAULT 0;
ALTER TABLE tasks ADD COLUMN plan_group INTEGER NOT NULL DEFAULT 0;
ALTER TABLE tasks ADD COLUMN parent_task_id TEXT;
```

新增数据库初始化语句位于 `server.js` 的 `db.exec` 建表区：

```sql
CREATE TABLE IF NOT EXISTS notes (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  content TEXT NOT NULL,
  side TEXT NOT NULL CHECK(side IN ('left','right')),
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_notes_user_side ON notes(user_id, side, created_at);
```

路由挂在 `server.js` 已有鉴权中间件之后：`GET/POST /api/notes`、`PUT/DELETE /api/notes/:id` 位于 `/api/auth/me` 后；`POST /api/ai-plan` 位于图片解析路由后。所有新接口均使用现有 `auth` 中间件。

## 邀请码注册与会话过期清理

为防止低配 VPS 被脚本恶意批量注册撑爆数据库、以及僵尸会话堆积耗尽内存，注册与会话增加了两层保护。全部为增量实现，不影响既有账户与数据，也不引入 Redis 等新组件。

### 邀请码注册

注册接口必须携带有效邀请码，否则直接拒绝。校验顺序：邀请码存在且启用 → 使用次数未达上限 → 事务内创建用户并消耗次数（`used_count < max_use_count` 条件更新兜底，并发不会超用；任一步失败整体回滚）。错误提示按「需要邀请码（400）/ 邀请码无效（403）/ 邀请码已用完（403）/ 请求过于频繁（429）」区分。

同一 IP 在 10 分钟内最多尝试注册 3 次（成功与失败都计入），超过返回 429。限流为进程内滑动窗口，服务重启后计数清零。

登录与注册按 IP 独立计数：默认 10 分钟内最多尝试登录 10 次，成功登录清零，失败保留计数。超限在查询用户和 bcrypt 比较前直接返回 429（`code: LOGIN_RATE_LIMITED`），并通过 `Retry-After` 返回剩余等待秒数；前端显示服务端提示和按钮倒计时，保留已填账户名与密码。超限请求不会延长封锁。两种限流均为进程内滑动窗口，重启服务后计数清零。

邀请码通过命令行维护，无需后台页面：

```powershell
npm run invite -- generate 5 "给朋友A"      # 生成邀请码，数字为最大可用次数（默认 1），后面可写备注
npm run invite -- list                      # 列出全部邀请码（已用/上限、状态、备注）
npm run invite -- disable QX-XXXX-XXXX-XXXX # 停用指定邀请码
```

### 会话双重超时与定期清理

`sessions` 表新增 `last_activity_at`（最后活跃时间）与 `expire_at`（绝对过期时间）两个毫秒时间戳字段。每次带 JWT 请求时服务端校验三重过期（原 JWT 过期、绝对超时、空闲超时），全部在服务端判断，不信任前端；通过校验后按节流间隔（默认 5 分钟）刷新 `last_activity_at`，避免高频请求写放大。

- 空闲超时：默认 24 小时无任何请求即失效；
- 绝对超时：默认 7 天，无论是否活跃强制失效；
- 定时清理：服务进程内置定时器，启动 30 秒后补跑一次，之后默认每 2 小时执行一轮。清理拆成 3 条单条件删除（分别命中 `expires_at`、`expire_at`、`last_activity_at` 三个索引），每批 100 条循环删完，避免全表扫描拖垮低配机器。

手动清理一次：

```powershell
npm run clean-sessions
```

### 配置项与迁移

以下均为可选项，写在 `.env` 中（参见 `.env.example`），未设置时使用默认值：

| 环境变量 | 默认值 | 含义 |
|---|---|---|
| `TRUST_PROXY` | `false` | 部署在 Nginx/Caddy 等反代后改为 `true`，否则限流会把所有请求算到代理 IP；直连时保持 `false` 防止伪造 `X-Forwarded-For` 绕过限流 |
| `REGISTER_WINDOW_MINUTES` | `10` | 注册限流窗口（分钟） |
| `REGISTER_MAX_ATTEMPTS` | `3` | 窗口内同 IP 最多注册尝试次数 |
| `LOGIN_WINDOW_MINUTES` | `10` | 登录限流窗口（分钟），与注册独立计数 |
| `LOGIN_MAX_ATTEMPTS` | `10` | 窗口内同 IP 最多登录尝试次数，成功登录清零 |
| `SESSION_IDLE_TIMEOUT_HOURS` | `24` | 会话空闲超时（小时） |
| `SESSION_ABSOLUTE_TIMEOUT_DAYS` | `7` | 会话绝对超时（天） |
| `SESSION_CLEANUP_INTERVAL_MINUTES` | `120` | 清理定时任务间隔（分钟） |
| `SESSION_CLEANUP_BATCH_SIZE` | `100` | 每批删除会话条数 |
| `SESSION_ACTIVITY_REFRESH_SECONDS` | `300` | 活跃时间刷新节流（秒） |

数据库变更为 `migrations/001_invite_codes_and_session_cleanup.sql`（邀请码与会话清理，第三次迭代）与 `migrations/002_user_settings_timetable.sql`（作息表补列，第四次迭代），可手动执行：

```powershell
sqlite3 data/qingxu.sqlite < migrations/001_invite_codes_and_session_cleanup.sql
sqlite3 data/qingxu.sqlite < migrations/002_user_settings_timetable.sql
```

不手动执行也可以：`server.js` 启动时会幂等完成同样的建表与补列（包括 `user_settings.timetable_json`），并把历史会话的活跃时间回填为创建时间、绝对过期沿用原 `expires_at`，已有用户不会被强制下线。升级前建议先备份整个 `data/` 目录。

冒烟测试已覆盖无邀请码（400）与无效邀请码（403）路径，`npm test` 会一并验证。
